Текущие ограничения:

- CMS product readiness не закрыта: пустые «Глобальные секции» и демо-кампании убраны из обычного меню; старый URL секций ведёт к главной, маркетинга — к пояснению со ссылкой на промокоды CRM. Несохраняемые поля intent/аудитории посадочных и фильтров категорий убраны из формы до появления реального контракта. `/redirects` читает реальные 301 из манифеста активной публикации, но ручное создание и проверка изменений адресов ещё не реализованы. `/seo` показывает реальные рабочие редакции, проверяет title/description и для отдельной страницы сравнивает четыре SEO-поля с активной публикацией; links/media/schema/sitemap и расширенный SEO flow ещё не проверяются. Для статей доступны текст и публичное имя автора; остаются изображения в теле и остальные авторские метаданные, полноценные settings/media flows, delivery status конкретной страницы и расширенная аналитика. `/settings/site` сохраняет и публикует название, контакты, описание и реквизиты подвала в общем черновике с перечислением сопутствующих изменений; домен и ссылки на юридические документы пока не редактируются. `/settings/access` показывает права текущей сессии без вымышленных сотрудников; изменение прав в UI пока недоступно. Редактор читает принадлежность страницы к активной публикации; реестр показывает только состояние редакции и прежнюю публикацию. Меню проверяет формат ссылок при сохранении; публикация настроек и страниц блокирует внутренние ссылки на страницы вне активного релиза. Обязательный объём по всем разделам и acceptance — раздел «CMS — доведение продукта до production» в `IMPLEMENTATION-ROADMAP.md`. Завершённые backend foundations не означают готовность полного UX.
- Публичная навигация показывает все три уровня меню на компьютере и телефоне, учитывает выключенные вложенные пункты; footer не теряет опубликованные колонки и ссылки и не заменяет пустой список демо-данными. Редактор меню предупреждает о других изменениях в общем черновике настроек перед публикацией. Опубликованные контакты из настроек используются в footer, меню, FAQ, окнах связи и кнопке сообщества; прежние значения служат fallback для старых публикаций. Описание и реквизиты footer читаются из того же источника.
- Старые `/components/*` ведут к редактируемым секциям главной вместо вымышленных пресетов. `/audit` не показывает фиктивных действий сотрудников: до появления scoped API там явное недоступное состояние и ссылка на реальную историю публикаций.
- «Снять с сайта» в редакторе создаёт новую активную публикацию без страницы и сохраняет её черновик/историю. Дочерние страницы и опубликованные внутренние ссылки блокируют снятие с объяснением причины. Прежний URL возвращает 404 и выходит из sitemap; страницу можно опубликовать снова. «Архивировать» по-прежнему не меняет active release.
- Booking/ProgramRegistration/Event принимают server-owned immutable quotes с exact context, versions и составом; preview не подтверждает заказ. Lifecycle/capacity/audit/outbox согласованы атомарно.
- Финансы смешанной брони пока показывают операции и оплату на уровне всего заказа и относят их к первой позиции. Разнос выручки по домику и бане/чану требует отдельного правила распределения суммы, скидки и возврата; текущий отчёт по категориям нельзя считать точным для таких заказов.
- Поддержаны назначенные quantity/person add-ons. Shared-capacity Event resources и scheduled-resource add-ons заблокированы; legacy manual/unpriced flows сохранены без автоматической миграции.
- CMS — editorial-only `/content/tree` и canonical drafts. Для сохранённых страниц тип редактора берётся из server node; альтернативные URL переводят к нему, несовместимый CRM locator блокируется. Operational pricing/fulfillment остаются в CRM; CMS draft сам по себе не даёт public eligibility. Customer Event не создаёт CMS draft или payment.
- DB tests требуют отдельную disposable test database и restricted role. Старые результаты прогонов — исторические, не текущий gate.
- Media production config fail-closed: `APP_ENV=production` требует S3-compatible bucket, CDN base URL, external HTTP scanner и upload signing secret; local storage/scanner остаются только development/test adapters.
- Standalone site runtime проверяется HTTP contract stub без БД; production backend/CDN/deployment gates этим не закрыты. Full-homepage visual baselines сверены с текущими секциями why-us/partners; стандартный site E2E теперь проходит. В локальной опубликованной главной две CRM-карточки домиков, две программы, две ближайшие даты и одна площадка. «Чайный мастер-класс» опубликован через CRM-тариф 1 600 ₽ за участника и CMS-страницу; фото помечено в медиатеке как демо-иллюстрация для замены перед запуском. У «Дома у озера» активная цена 8 000 ₽ также приходит из CRM, фото имеет такую же пометку. «Поляна для праздника» показывает действующую CRM-цену 2 200 ₽ за час. «Лесной дом» сохранил старый технический URL и noindex, но больше не показывает служебное название на сайте. На главной пока меньше карточек, чем в старом демо-макете: нужны дополнительные примеры в CRM с опубликованными CMS-страницами. Public API не подставляет фиктивные карточки.
- Главная читает published public summaries домиков/программ/площадок/допов, афиша — ближайшие открытые проведения программ. В CMS выбор и порядок карточек домиков, программ и площадок задаются в соответствующих секциях главной через CRM IDs; карточки без опубликованной public projection не появляются. Старые секции без выбора сохраняют автоматическую выдачу. Направления программ, визуальные карточки бани/чана и ролики отзывов редактируются в тех же секциях главной без отдельных сущностей; для ролика указывают прямой HTTPS MP4/WebM и обложку, старые фото остаются видимыми до замены. Если у включённых секций событий, программ или площадок нет CRM-карточек, остаются заголовок и пустое состояние; у бани/чана до safe scheduled-resource contract показываются редакционные карточки с обращением к менеджеру без цены. Цены программ, площадок и событий обновляются из CRM при следующем запросе без новой CMS-публикации; no-store и один release проверяются. В CMS управляются слайды и карточки первого экрана, плашка и до трёх CRM-промокодов; текущие условия и доступность промокодов обновляются без новой публикации. Изображение operational карточек, афиши и hero берётся из опубликованных CMS media; при отсутствии файла тестовое фото не подставляется. Локальный сайт проксирует только публичные варианты медиа API. Map/directions требуют отдельного контентного подключения.

## Следующий инкремент

1. CMS: продолжить media lifecycle (isolated проверка ошибок и расширенный usage) и оставшиеся C3–C10. Первый запуск главной и живые CRM-промокоды прошли HTTP/PostgreSQL integration; отдельный browser → API → public renderer E2E проверяет первый выпуск, изменение и откат главной на desktop/mobile. Локально через UI редактора проверены сохранение, подписанный noindex-предпросмотр, публикация и появление текста на сайте; у новой версии delivery для analytics и SSE завершился успешно. Replay для ошибочной доставки ещё требует отдельной проверки. Дальше — scheduled-resource contract бани/чана и остальные media flows по roadmap. Сохранность редактора, FAQ/отзывы, hero media и история редакций уже реализованы; новые формы переиспользуют этот flow.
2. Параллельно закрыть go-live media decisions: provider/data-location/retention approval и rights/source review для approved media migration.
3. После надёжного редакционного ядра расширять P4.7 attribution linkage/models; минимальная аналитика должна честно отражать уже поддержанные измерения.

До go-live выбрать production media storage/CDN (хранение файлов и их публичная доставка), утвердить legal/privacy/retention и deployment gates. При выборе объяснить пользователю варианты и последствия; provider-neutral разработку это не блокирует.

## Границы

- `apps/admin` использует `packages/ui`, CRM session/capabilities и общие API contracts.
- CRM владеет resources, availability/capacity, prices, Lead/Booking/Payment; CMS — public profiles, copy, media, composition, SEO и publication.
- Standard pages — Astro templates + typed CMS fields; unique source pages — только `apps/site/src/managed/**`.
- CMS не исполняет TSX/HTML из БД. Custom code проходит allowlisted workspace, isolated build, review, atomic release и rollback.
- Public output привязан к immutable active release; draft/media originals/internal relations/PII наружу не выходят.
- First-party analytics использует opaque visitor/session IDs и server conversion facts; raw IP, contacts и form values не пишутся в analytics events.
