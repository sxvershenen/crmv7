# Content backlog and calendar model

Реальные темы и cadence будут определены после семантики/конкурентного исследования и подтверждения ресурсов команды. Сейчас фиксируется исполнимый backlog миграции и структура календаря.

## 1. P4 migration backlog

1. Global identity/navigation/footer/contact/legal facts.
2. Home sections and default hero/tail presets.
3. Existing public resource pages and redirects.
4. Listing hubs: houses, additions, venues, programs, events.
5. Public profiles for real CRM entities selected for publication.
6. Current blog listing/articles after content verification.
7. Directions, FAQ, contacts, privacy.
8. Curated categories/landings supported by evidence.

## 2. Calendar fields in CMS

- content item/page/release;
- pillar and intent;
- owner, author, reviewer;
- status and blockers;
- due/review/publish/unpublish dates;
- dependencies: CRM entity, media, code, legal/SEO review;
- target related pages and links;
- campaign;
- revision/content version;
- post-publish review date and outcome.

## 3. Workflow

`Idea/evidence → Brief → Draft → Editorial review → SEO/claims review → Approved → Scheduled → Published → Measured → Refresh/Archive`.

Calendar does not become a second task manager: work item can link to CRM Task; CMS owns content status and release date.

## 4. Quality rule

No invented article titles, promotions, prices, claims, schedules or publishing cadence are part of this baseline. Each future item needs a real intent, owner, evidence/source and internal-link role.
