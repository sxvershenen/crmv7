# Scheduler / Agenda — общий паттерн

## Исходные визуальные требования

Для ресурсов и домиков используем Vertical Scheduler с шагом в час. Карточки должны быть dnd + иметь по краям сверху и снизу поля для растягивания или сужение времени, при изменении карточки сразу же показывать в превью какое время выставится. Так же визуализировать блокировку на подготовку после брони.
Подтверждено - голубоватая карточка, ожидание/неподтверждено - жёлтая, красная - конфликт, зелёная - оплачено полностью.
Клик по пустому место открывает страницу создания новой записи.
При этом планировщик должен иметь бесконечный скролл вверх и вниз по дням, но надо чтобы дни помечались как то что новый день начался.

## Общие технические/UX-ограничения

- Scheduler не должен иметь горизонтальный scroll как основной способ навигации периода, если его можно избежать адаптивным масштабом/контролами периода.
- Scheduler использует вертикальную ось времени. На desktop ресурсы показываются адаптивными lane-колонками без постоянного горизонтального scroll; лишние ресурсы доступны через поиск и постраничное переключение набора lane.
- DnD/resize всегда показывают preview нового интервала до commit.
- После commit будущий backend повторно валидирует availability; frontend обязан уметь rollback/conflict state.
- Подготовительный интервал визуализируется отдельно от фактической брони.
- Capacity resource показывает `занято X / Y`/progress.
- Mobile: agenda/day-centric управление по умолчанию; явно выбранный Scheduler показывает одну resource lane с вертикальной осью времени, а не уменьшенную копию desktop.
- Нужна keyboard/touch альтернатива DnD/resize.
